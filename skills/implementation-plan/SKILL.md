# Implementation Plan

Use after repository investigation and before non-trivial edits.

1. Restate the requested outcome in repository terms.
2. Identify the files/components likely to change and why.
3. Identify existing patterns that should be reused.
4. List risks, compatibility concerns, migrations, external dependencies and security boundaries.
5. Define observable acceptance criteria before implementation.
6. Define the minimum verification needed to prove those criteria.
7. Prefer the smallest coherent implementation. Avoid speculative abstractions and unrelated cleanup.
8. If a required decision cannot be resolved from repository evidence, isolate it and ask only that question.

The plan is a working contract, not ceremony. Update it when repository evidence disproves an assumption.
